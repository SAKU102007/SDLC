# ADR-001: Выбор архитектурного стиля приложения (Модульный монолит на ASP.NET Core 8 MVC)

## Контекст и постановка задачи

Для веб-приложения «LabReportValidator» требуется определить архитектурный стиль, обеспечивающий быстродействие, простоту развёртывания, низкую стоимость владения и возможность постепенной модификации компонентов валидации и антиплагиата. Проект реализуется компактной командой в сжатые сроки учебного семестра.

## Драйверы решения

* Ограниченные сроки разработки (4 недели активной фазы).
* Команда: 1 ведущий разработчик и 1 junior-разработчик.
* Требование к отклику страниц ≤ 2 с (REQ-PERF-001).
* Требование к надёжности и транзакционной целостности данных в СУБД PostgreSQL (REQ-INT-004, REQ-REL-001).

## Рассмотренные варианты

* Вариант 1: Клиент-серверное SPA-приложение (React / Vue) + REST API на ASP.NET Core Web API.
* Вариант 2: Микросервисная архитектура (отдельные сервисы авторизации, парсинга, антиплагиата, уведомлений).
* Вариант 3: Серверный модульный монолит на ASP.NET Core 8 MVC с серверным рендерингом Razor.

## Оценка вариантов

### Вариант 1: SPA + REST API
* Плюсы: разделение фронтенда и бэкенда, богатый клиентский интерактив.
* Минусы: двойной стек технологий (JS/TS и C#), необходимость отдельной сборки и маршрутизации, дублирование моделей данных, увеличенное время разработки.

### Вариант 2: Микросервисы
* Плюсы: независимое масштабирование сервиса антиплагиата.
* Минусы: колоссальный оверхед на оркестрацию, сетевые задержки, распределённые транзакции, избыточная сложность для учебного проекта.

### Вариант 3: Модульный серверный монолит на ASP.NET Core 8 MVC
* Плюсы: единый технологический стек C# / .NET 8, высокая скорость разработки, серверная генерация HTML снижает нагрузку на браузер, простое развёртывание одним процессом, нулевой оверхед на межсервисную сеть, изолированные слои сервисов.
* Минусы: горизонтальное масштабирование выполняется целиком для всего приложения.

## Итоговое решение

Принят **Вариант 3: Модульный серверный монолит на ASP.NET Core 8 MVC**. Архитектура разделяется на изолированные логические сборки (Web, Core/Business Logic, DataAccess), что гарантирует слабую связанность и тестируемость модулей.
