## 1. Введение

### 1.1. Назначение документа
Настоящий документ представляет собой Спецификацию требований к программному обеспечению (SRS) для системы «LabReportValidator» версии 0.2. Документ определяет функциональные и нефункциональные требования, ограничения и критерии приёмки, которые должны быть реализованы в релизной версии 1.0. Спецификация является основой для разработки архитектуры (SDD), проектирования базы данных, написания кода и приёмочного тестирования.

### 1.2. Область применения продукта
Система «LabReportValidator» — это веб-приложение, предназначенное для автоматизации процесса загрузки, проверки и рецензирования отчётов по лабораторным работам. 
Продукт решает проблемы ручной проверки оформления, предотвращает плагиат путём глобального сравнения работ и автоматизирует уведомление преподавателей о нарушениях.

**Входит в объём версии 1.0:**
- Аутентификация и авторизация (студент, преподаватель, администратор).
- Загрузка файлов (PDF, DOCX) и контроль версий.
- Автоматическая валидация структуры отчёта (5 разделов).
- Глобальная проверка на антиплагиат (порог 30%).
- Модуль уведомлений и конечный автомат статусов.
- Панели управления для преподавателя и администратора.

**Не входит в версию 1.0 (Бэклог):**
- Интеграция с внешними облачными API антиплагиата (SaaS).
- Мобильные нативные приложения.
- Автоматическое выставление оценок без участия преподавателя.

## 2. Обзор продукта

### 2.1. Перспектива продукта
Система является трёхзвенным веб-приложением. Клиентская часть работает в браузере (Chrome, Firefox, Edge) и взаимодействует с сервером по HTTPS. Серверная часть реализована на ASP.NET Core 8 MVC (Kestrel). Данные хранятся в реляционной СУБД PostgreSQL 16. Взаимодействие с БД осуществляется через Entity Framework Core.

### 2.2. Функции продукта
- **F-01:** Каркас системы, управление пользователями и ролями (RBAC).
- **F-02:** Кабинет студента (список работ, отслеживание статусов).
- **F-03:** Загрузка файлов, парсинг документов и версионность.
- **F-04:** Валидация структуры отчёта по заданному шаблону.
- **F-05:** Глобальный антиплагиат (сравнение со всей базой отчётов).
- **F-06:** Панель преподавателя (рецензирование, просмотр результатов).
- **F-07:** Панель администратора (управление справочниками).
- **F-08:** Модуль уведомлений и конечный автомат статусов.

### 2.3. Ограничения продукта

| ID | Ограничение | Обоснование |
|---|---|---|
| **CON-01** | Стек: C# / ASP.NET Core 8 MVC. | Требование Заказчика, опыт команды, ADR-001. |
| **CON-02** | СУБД: PostgreSQL 16. | Необходимость GIN-индексов для быстрого поиска, ADR-002. |
| **CON-03** | Порог антиплагиата: строго 30%. | Требование преподавателя (Раунд 2). |
| **CON-04** | Срок сдачи релиза: 22.12.2026. | Согласованный перенос дедлайна (Раунд 2). |
| **CON-05** | Бюджет: 5 922 BYN. | Фиксированный бюджет на 141 час работы (Раунд 2). |

### 2.4. Характеристики пользователей
- **Студент:** Загружает отчёты, следит за статусом проверки, получает уведомления о возврате на доработку.
- **Преподаватель:** Просматривает отчёты, получает уведомления о плагиате, выносит вердикт (оценку).
- **Администратор:** Управляет пользователями, дисциплинами и шаблонами отчётов.

### 2.5. Допущения и зависимости
- **A1:** Пользователи имеют доступ к современным десктопным браузерам.
- **A2:** Сервер развёрнут в среде с поддержкой Docker (Kestrel + PostgreSQL).
- **D1:** Наличие SMTP-сервера для отправки email-уведомлений.
- **D2:** Доступность ведущего разработчика в объёме 141 часа.

### 2.6. Распределение требований по релизам
- **Релиз 1.0 (Must Have):** Все требования REQ-FUNC-001..016, REQ-SEC-001..003, REQ-PERF-001..003. Срок: 22.12.2026.
- **Релиз 1.1 (Should Have):** Экспорт статистики в CSV, расширенная аналитика.
- **Бэклог (Could Have):** Мобильный клиент, интеграция с внешними SaaS.

## 3. Требования

### 3.1. Внешние интерфейсы

#### 3.1.1. Пользовательские интерфейсы
**REQ-INT-001 — Навигация и адаптивность**
- **Описание:** Веб-интерфейс должен корректно отображаться в браузерах Chrome, Firefox, Edge при разрешении от 1024x720. Навигация осуществляется через боковое меню.
- **Приоритет:** 20 (Высокий).
- **Критерий приёмки:** Отсутствие горизонтальной прокрутки на указанных разрешениях, корректная работа навигации.

**REQ-INT-002 — Формы загрузки и рецензирования**
- **Описание:** Форма загрузки должна содержать выбор дисциплины, номера ЛР и поле для файла (PDF/DOCX). Панель преподавателя должна отображать метаданные отчёта и результаты проверок.
- **Приоритет:** 10 (Критический).
- **Критерий приёмки:** Валидация полей формы на клиенте и сервере.

#### 3.1.2. Программные интерфейсы
**REQ-INT-003 — Взаимодействие с СУБД**
- **Описание:** Сервер приложений подключается к PostgreSQL 16 через TCP/IP с использованием EF Core. Порт 5432 закрыт для внешних подключений.
- **Приоритет:** 10 (Критический).
- **Критерий приёмки:** Прямой доступ к БД извне невозможен.

**REQ-INT-004 — SMTP-интеграция**
- **Описание:** Для отправки email-уведомлений сервер использует SMTP-протокол (порт 587/TLS).
- **Приоритет:** 10 (Критический).
- **Критерий приёмки:** Успешная отправка тестового письма.

### 3.2. Функциональные требования

#### Управление доступом
**REQ-FUNC-001 — Регистрация и роли**
- **Описание:** Система должна поддерживать регистрацию пользователей с ролями: Студент, Преподаватель, Администратор. Регистрация по Email и паролю.
- **Приоритет:** 10.
- **Критерий приёмки:** Разграничение прав доступа согласно матрице ролей.

**REQ-SEC-001 — Аутентификация (JWT)**
- **Описание:** Авторизация выполняется с помощью JWT-токенов. Пароли хранятся в виде хешей BCrypt.
- **Приоритет:** 10.
- **Критерий приёмки:** Время жизни токена 60 минут, при истечении — обновление или повторный вход.

#### Работа с отчётами
**REQ-FUNC-002 — Загрузка файлов**
- **Описание:** Студент может загрузить файл отчёта в формате PDF или DOCX размером до 10 МБ.
- **Приоритет:** 10.
- **Критерий приёмки:** Файлы иных форматов или превышающие лимит отклоняются с сообщением об ошибке.

**REQ-FUNC-003 — Версионность**
- **Описание:** При повторной загрузке отчёта по той же ЛР создаётся новая версия. История версий сохраняется.
- **Приоритет:** 10.
- **Критерий приёмки:** В БД создаётся новая запись в таблице `ReportVersion`, предыдущие версии остаются доступными для аудита.

**REQ-FUNC-004 — Извлечение текста**
- **Описание:** Система должна извлекать текст из PDF (PdfPig) и DOCX (DocumentFormat.OpenXml).
- **Приоритет:** 10.
- **Критерий приёмки:** Корректное извлечение кириллицы и латиницы без потери структуры абзацев.

**REQ-FUNC-005 — Валидация структуры**
- **Описание:** Система проверяет наличие 5 обязательных разделов в тексте отчёта согласно шаблону.
- **Приоритет:** 10.
- **Критерий приёмки:** При отсутствии хотя бы одного раздела отчёт переводится в статус «Шаблон» (`StructureRejected`).

#### Антиплагиат
**REQ-FUNC-007 — Глобальная проверка**
- **Описание:** Текст отчёта разбивается на шинглы (k=4) и сравнивается с хэшами всех ранее загруженных отчётов в БД.
- **Приоритет:** 20.
- **Критерий приёмки:** Поиск по базе из 10 000 отчётов занимает не более 15 секунд.

**REQ-FUNC-008 — Порог 30% и блокировка**
- **Описание:** Если максимальный процент совпадения ≥ 30.0%, отчёт отклоняется (статус `PlagiarismRejected`), а студенту блокируется повторная отправка до внесения правок.
- **Приоритет:** 10.
- **Критерий приёмки:** Срабатывание порога строго при значении ≥ 30.0%.

#### Уведомления и статусы
**REQ-FUNC-015 — Модуль уведомлений**
- **Описание:** При фиксации плагиата преподавателю отправляется уведомление (в интерфейсе + на Email) с указанием автора, процента совпадения и источников.
- **Приоритет:** 10.
- **Критерий приёмки:** Уведомление доставляется в течение 1 минуты после завершения проверки.

**REQ-FUNC-016 — Конечный автомат статусов**
- **Описание:** Статусы отчёта делятся на 4 категории:
  1. *Обработка:* `Uploaded`, `Validating`.
  2. *Шаблон:* `StructureRejected`.
  3. *Антиплагиат:* `PlagiarismRejected`.
  4. *Рецензирование:* `UnderReview`, `RevisionRequired`, `Accepted`, `Graded`.
  Флаг `Overdue` устанавливается независимо при просрочке дедлайна.
- **Приоритет:** 10.
- **Критерий приёмки:** Недопустимые переходы между статусами блокируются на уровне бизнес-логики.

#### Панели управления
**REQ-FUNC-009..012 — Панель преподавателя**
- **Описание:** Преподаватель видит отчёты на проверке, результаты валидации и антиплагиата, может выставить оценку.
- **Приоритет:** 30.

**REQ-FUNC-013..014 — Панель администратора**
- **Описание:** Управление пользователями, дисциплинами, потоками и шаблонами отчётов.
- **Приоритет:** 40.

### 3.3. Требования к качеству обслуживания

**REQ-PERF-001 — Время отклика UI**
- Все страницы должны загружаться не более чем за 2.0 секунды при нормальной нагрузке. (Приоритет: 10).

**REQ-PERF-002 — Скорость валидации**
- Проверка структуры файла до 10 МБ должна занимать не более 5 секунд. (Приоритет: 20).

**REQ-REL-001 — Надёжность транзакций**
- Смена статусов и сохранение результатов проверки должны выполняться в рамках ACID-транзакций СУБД PostgreSQL. (Приоритет: 10).

**REQ-SEC-002 — Изоляция данных**
- Студенты имеют доступ только к своим отчётам. Преподаватели — только к отчётам своих дисциплин. (Приоритет: 10).

## 5. Приложения

### 5.1. Основные сценарии использования (Use Cases)

**UC-01: Успешная загрузка отчёта**
1. Студент выбирает дисциплину и ЛР.
2. Загружает файл PDF.
3. Система сохраняет версию, запускает парсинг.
4. Структура валидна. Антиплагиат показывает 12%.
5. Статус меняется на `UnderReview`. Студент видит, что отчёт принят.

**UC-02: Отклонение из-за плагиата**
1. Студент загружает отчёт.
2. Структура валидна.
3. Антиплагиат находит совпадение 45% с работой другого студента.
4. Статус меняется на `PlagiarismRejected`.
5. Студенту блокируется повторная отправка.
6. Преподавателю уходит Email и Push-уведомление со ссылкой на источники.

### 5.2. Модель данных (Ключевые сущности)
- **User** (Id, Email, PasswordHash, Role).
- **Subject** (Id, Name, TeacherId).
- **LabWork** (Id, SubjectId, Number, Title, Deadline).
- **Report** (Id, StudentId, LabWorkId, CurrentStatus, IsOverdue).
- **ReportVersion** (Id, ReportId, FilePath, Format, UploadDate).
- **ValidationResult** (Id, VersionId, IsStructureValid, MissingSections).
- **PlagiarismMatch** (Id, VersionId, SourceReportId, SimilarityPercent).
- **Notification** (Id, UserId, Message, IsRead, CreatedAt).
